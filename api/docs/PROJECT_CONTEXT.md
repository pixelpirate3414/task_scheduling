# Контекст проекта API

## Назначение микросервиса

`api` — HTTP API сервиса управления задачами. Он предоставляет регистрацию и вход пользователей, выдачу данных текущего пользователя и операции над его задачами. Доступ к задачам привязан к аутентифицированному владельцу.

## Стек

- Java 25 (Gradle toolchain), Gradle Kotlin DSL.
- Spring Boot 4.1.2: Spring MVC для HTTP API, Spring Data JPA для хранения данных, Spring Security и OAuth2 Resource Server для защиты API.
- JWT для аутентификации; конфигурационный секрет задается через `JWT_SECRET`.
- PostgreSQL как основная база данных.
- Liquibase для миграций схемы; Hibernate работает в режиме `ddl-auto: validate`.
- springdoc OpenAPI для документации HTTP API.
- MapStruct и Lombok для преобразований DTO и сокращения шаблонного кода.

## Зона ответственности

Сервис отвечает за:

- регистрацию пользователя и вход по email и паролю;
- получение сведений о текущем пользователе;
- создание, получение, удаление, завершение и повторное открытие задач;
- проверку прав на задачи через привязку к владельцу;
- валидацию входных DTO, преобразование ошибок в HTTP-ответы;
- хранение пользователей и задач и управление схемой базы данных.

Модель задачи содержит заголовок, необязательное описание, статус, время создания и время завершения. Поддерживаются статусы `IN_PROGRESS` и `DONE`. Отдельные функции планирования по времени, фонового исполнения и уведомлений в текущем коде не реализованы.

## Архитектура

Приложение организовано слоями в пакете `com.taskscheduller.api` (написание `taskscheduller` намеренно соответствует существующему коду):

1. **Контроллеры** (`controller`) принимают HTTP-запросы под `/api/auth`, `/api/user` и `/api/tasks`, используют DTO и вызывают сервисы. Интерфейсы документации контроллеров находятся в `controller/docs`.
2. **Сервисы** (`service`, `service/impl`) содержат сценарии регистрации, аутентификации и управления задачами/пользователями.
3. **Репозитории** (`repository`) обеспечивают доступ к данным через Spring Data JPA.
4. **Сущности** (`entity`) описывают пользователя и задачу; связь задач с владельцем — многие-к-одному.
5. **DTO и мапперы** (`dto`, `mapper`) отделяют HTTP-контракты от JPA-модели.
6. **Безопасность и конфигурация** (`security`, `config`) настраивают JWT, загрузку пользователя, обработку неавторизованных запросов, Jackson и OpenAPI.
7. **Liquibase changelog** в `src/main/resources/db/changelog` задает схему базы данных.

Поток запроса: HTTP-контроллер → прикладной сервис → репозиторий → PostgreSQL; результат преобразуется в response DTO. Защищенные запросы проходят проверку Spring Security, а идентификатор владельца берется из контекста аутентификации.

## Конфигурация и точки входа

- Основная конфигурация: `src/main/resources/application.yaml`.
- Параметры подключения к PostgreSQL задаются переменными `POSTGRES_URL`, `POSTGRES_USER`, `POSTGRES_PASSWORD`; предусмотрены локальные значения по умолчанию.
- Файл `.env` может подключаться локально через optional config import; секреты не следует помещать в документацию или коммитить.
- Liquibase changelog: `src/main/resources/db/changelog/db.changelog-master.yaml`.
- Точка входа приложения: `src/main/java/com/taskscheduller/api/ApiApplication.java`.
